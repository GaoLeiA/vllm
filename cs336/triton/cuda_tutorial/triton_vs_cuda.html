Triton vs CUDA 深度解析

从底层视角理解 Triton 是如何抽象并简化 GPU 编程的

第一章: 编程模型差异 (Hello Kernel)

Triton 和 CUDA 最大的区别在于并发抽象的层级。CUDA 要求开发者管理 Grid、Block 和单个 Thread，而 Triton 要求开发者只需要管理到 Block 层级（SIMD/SIMT 级别的向量化），编译器会自动将 Block 内的计算分配给具体的 Thread。

Triton (Python) 
@triton.jit
def hello_kernel(x_ptr, y_ptr, n_elements, BLOCK_SIZE: tl.constexpr):
    # 1. 获取当前 Block 的 ID
    pid = tl.program_id(axis=0)
    
    # 2. 生成一个 Block 内所有元素的偏移量数组
    block_start = pid * BLOCK_SIZE
    offsets = block_start + tl.arange(0, BLOCK_SIZE)
    
    # 3. 边界遮罩 (Mask)
    mask = offsets < n_elements
    
    # 4. 向量化加载与计算
    x = tl.load(x_ptr + offsets, mask=mask)
    tl.store(y_ptr + offsets, x + 1, mask=mask)
CUDA C++ 
__global__ void hello_kernel(
    const float* x, float* y, int n_elements) {
    
    // 1. 计算当前 *单个 Thread* 的全局索引
    // blockIdx.x 对应 tl.program_id(0)
    // threadIdx.x 对应 tl.arange(...) 中的某个特定值
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    
    
    // 2. 标量级别的边界检查
    if (idx < n_elements) {
        
        // 3. 标量计算，所有线程并发执行这行代码
        y[idx] = x[idx] + 1.0f;
    }
}
💡 细节解析：
  • tl.program_id(0) 完全等价于 CUDA 中的 blockIdx.x。它们都代表当前执行的线程块编号。
  • Triton 的核心魔法在于 tl.arange。在 Triton 中，你写出的代码处理的是向量（一个 Block 内的所有元素）。Triton 编译器在编译时，会自动将这些向量操作映射为 CUDA 中对应的 threadIdx.x 标量操作。
  • Triton 使用 mask 来处理数组越界，这对应底层指令的 Predicate；而在 CUDA 中，我们直观地使用 if (idx < n) 分支。

第二章: 元素级操作 (Elementwise)

元素级操作中，线程间不存在依赖，因此两种语言的表达非常类似。Triton 直接利用其内建的数学库，CUDA 则使用设备内建的 C 数学库（如 fmaxf, expf, tanhf）。

Triton (GeLU)
# GeLU 激活函数实现
a = 0.79788456 * (x + 0.044715 * x * x * x)
exp_2a = tl.exp(2 * a)
# Triton 没有直接的 tanh，通过 exp 自己拼装
tanh_a = (exp_2a - 1.0) / (exp_2a + 1.0)
y = 0.5 * x * (1.0 + tanh_a)
CUDA C++ (GeLU)
// CUDA 内置了极快的原生 tanhf 函数
float val = x[idx];
float a = 0.79788456f * (val + 0.044715f * val * val * val);

float tanh_a = tanhf(a); // 硬件加速
y[idx] = 0.5f * val * (1.0f + tanh_a);
💡 细节解析：
  • Triton 的内建函数库 (如 tl.exp) 最终也会被 PTX 编译器映射为相同的硬件指令。
  • 在 CUDA 中，我们常使用带有 f 后缀的函数（如 expf，tanhf）来确保执行的是单精度（FP32）计算。如果在 CUDA 中写 exp()，可能会被提升为双精度（FP64），导致性能剧烈下降，Triton 帮用户规避了这种数据类型陷阱。

第三章: 行级聚合 (Softmax)

这里是 Triton 展现真正威力的地方！ 行级聚合（如找最大值、求和）需要在线程间通信。在 GPU 中，同一 Block 内的线程通过共享内存 (Shared Memory) 进行通信。Triton 完全隐藏了共享内存的分配和树形归约 (Tree Reduction) 的复杂逻辑。

Triton (Softmax 最大值与求和)
# 加载一整行 (向量化)
row = tl.load(x_ptr + offsets, mask=mask)

# 1. 找最大值：只需 1 行代码！
row_max = tl.max(row, axis=0)

# 2. 减去最大值并求 exp
numerator = tl.exp(row - row_max)

# 3. 求和：只需 1 行代码！
denominator = tl.sum(numerator, axis=0)
CUDA C++ (Softmax 找最大值)
extern __shared__ float sdata[]; // 手动声明共享内存

// --- 第一步：每个线程找自己负责元素的局部最大值 ---
float local_max = -INFINITY;
for (int col = threadIdx.x; col < N; col += blockDim.x) {
    local_max = fmaxf(local_max, x_row[col]);
}
sdata[threadIdx.x] = local_max;
__syncthreads(); // 等待所有线程写入完毕

// --- 第二步：树形归约 (Tree Reduction) ---
// 对应 Triton 编译器在后台自动生成的操作
for (int s = blockDim.x / 2; s > 0; s >>= 1) {
    if (threadIdx.x < s) {
        sdata[threadIdx.x] = fmaxf(
            sdata[threadIdx.x], 
            sdata[threadIdx.x + s]
        );
    }
    __syncthreads(); // 每次规约都必须同步！
}
float row_max = sdata[0]; // 最终结果存放在 0 号位置
💡 细节解析：
  • Triton 中的 tl.max(axis=0) 在 CUDA 中需要近 15 行代码来实现！
  • Shared Memory (__shared__)： 在 CUDA 中，必须手动开辟一块靠近计算单元的 L1 级别缓存来交换数据。Triton 编译器会根据 tl.max 等需要规约的函数，自动分析并在后台分配合适的共享内存。
  • Barrier 同步 (__syncthreads)： GPU 线程是高度并行的，读写共享内存时极易发生数据竞争（Race Condition）。在 CUDA 中必须极为严谨地插入同步点；Triton 编译器（基于 MLIR）会自动在需要的地方安插同步指令。

第四章: 矩阵乘法 (Tiled MatMul)

为了达到极致性能，矩阵乘法必须使用 Tiling (分块) 技术，将数据分块加载到共享内存中复用。Triton 原生以 Block (Tile) 为一等公民，极大地简化了这一设计模式。

Triton (Tiled MatMul 内循环)
# acc 初始化
acc = tl.zeros((BLOCK_SIZE_M, BLOCK_SIZE_N), dtype=tl.float32)

for k in range(0, tl.cdiv(K, BLOCK_SIZE_K)):
    # 1. 加载 A 和 B 的 Block
    a = tl.load(a_ptrs, mask=a_mask, other=0.0)
    b = tl.load(b_ptrs, mask=b_mask, other=0.0)
    
    # 2. 执行矩阵乘法 (自动使用 Tensor Cores 和 SRAM)
    acc += tl.dot(a, b)
    
    # 3. 指针步进
    a_ptrs += BLOCK_SIZE_K * stride_ak
    b_ptrs += BLOCK_SIZE_K * stride_bk
CUDA C++ (Tiled MatMul 内循环)
// CUDA: 手动声明 A 和 B 的 Shared Memory Tiles
__shared__ float As[TILE_SIZE][TILE_SIZE];
__shared__ float Bs[TILE_SIZE][TILE_SIZE];

for (int t = 0; t < num_tiles; t++) {
    // 1. 每个线程合作加载元素到 Shared Memory
    As[threadIdx.y][threadIdx.x] = A[row * K + a_col];
    Bs[threadIdx.y][threadIdx.x] = B[b_row * N + col];
    
    __syncthreads(); // 等待整个 Tile 加载完成

    // 2. 在 Shared Memory 内完成点积运算
    #pragma unroll
    for (int k = 0; k < TILE_SIZE; k++) {
        sum += As[threadIdx.y][k] * Bs[k][threadIdx.x];
    }
    
    __syncthreads(); // 等待计算完成才能加载下一个 Tile
}
💡 细节解析：
  • Triton 中的 tl.dot(a, b) 是一个极其重量级的操作符！它在编译器后端会自动完成：(1) 将 a 和 b 发送到共享内存；(2) 调整内存排布（Swizzling）以避免 Shared Memory Bank Conflict；(3) 调用 NVIDIA Tensor Cores（如果维度满足要求且为 FP16/BF16）。
  • 在 CUDA 原生实现中，如果要用 Tensor Cores 需要调用非常底层的 mma.sync PTX 指令或使用复杂的 wmma API，门槛极高。我们在上述 CUDA 教程中使用的是普通的 FP32 CUDA Core 计算。

第五章: FlashAttention (复杂融合)

FlashAttention 结合了 Online Softmax 和 Tiled Matmul。因为需要在同一个内循环中同时做求最大值、动态缩放、和矩阵乘法，它的 CUDA 原生实现极度复杂，需要仔细编排共享内存复用。而 Triton 则能保持数学表达的清晰度。

Triton (Online Softmax 更新)
# S_ij = Q @ K^T
qk = tl.dot(q, k) * sm_scale

# 结合上一个 Block 的 max
m_i_new = tl.maximum(m_i, tl.max(qk, axis=1))
alpha = tl.exp(m_i - m_i_new)

# P = exp(S_ij - max)
p = tl.exp(qk - m_i_new[:, None])

# 修正旧的累加并加入新值
l_i_new = alpha * l_i + tl.sum(p, axis=1)
acc = alpha[:, None] * acc + tl.dot(p, v)
CUDA C++ (Online Softmax 更新片段)
// CUDA: Q@K^T 需手动 Reduction 求出 S_ij，存在 shared memory
float m_new = fmaxf(m_acc, m_block); // 当前 max
float alpha = expf(m_acc - m_new);

// 修正旧值
o_acc *= alpha;
l_acc *= alpha;

// P @ V 内循环展开 (每个线程处理特征维度 d)
for (int j = 0; j < k_len; j++) {
    float p_j = expf(s_scores[j] - m_new);
    const float* v_row = v_base + (k_start + j) * D;
    
    if (d < D) {
        o_acc += p_j * v_row[d];
    }
    l_acc += p_j;
}
💡 细节解析：
  • 在 FlashAttention 中，Triton 仍然能够维持矩阵级别（tl.dot）和向量级别（tl.max）的抽象，让算法工程师能直接将数学公式翻译为代码。
  • 在 CUDA 中，开发者必须非常小心：不仅要为 Q、K、V 的块分配共享内存，还要为 reduction 中间结果（如 s_scores）规划内存。这就导致 FlashAttention 的底层 C++ 实现动辄上千行，而 Triton 版本仅需百余行。
